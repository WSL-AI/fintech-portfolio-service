# Система управления финансовым портфелем

Учебный проект на C++ для курсовой работы по объектно-ориентированному проектированию и программированию.

Тема проекта: автоматизированная система управления финансовым портфелем, в котором могут находиться акции, облигации и криптовалюты.

Сейчас в репозитории находится только минимальная основа программы. Она специально сделана небольшой, чтобы сначала разобраться с классами, наследованием и полиморфизмом, а затем постепенно добавлять остальные требования курсовой работы.

## Что должна делать готовая программа

После завершения курсовой программа должна позволять пользователю:

1. Войти в систему под своей учётной записью.
2. Работать в соответствии со своей ролью: администратор, менеджер или обычный пользователь.
3. Просматривать акции, облигации и криптовалюты.
4. Добавлять, изменять и удалять финансовые инструменты.
5. Создавать один или несколько финансовых портфелей.
6. Добавлять инструменты в портфель и указывать их количество.
7. Выполнять учебные операции покупки и продажи без использования реальных денег.
8. Рассчитывать стоимость отдельной позиции и всего портфеля.
9. Искать инструменты по названию или обозначению, например `AAPL` или `BTC`.
10. Сортировать и фильтровать инструменты по типу, названию и цене.
11. Загружать исходные данные из CSV, а в дальнейшем — из Parquet.
12. Сохранять пользователей, портфели и операции в файлы.
13. Формировать текстовый отчёт о составе и стоимости портфеля.
14. Обрабатывать ошибки: неверный ввод, отсутствующий файл, неправильный пароль, недостаток средств и попытку продать отсутствующий актив.

## Что уже реализовано

На текущем этапе программа:

- создаёт одну акцию, одну облигацию и одну криптовалюту;
- хранит разные виды инструментов в одном контейнере;
- выводит название, обозначение, тип и цену каждого инструмента;
- демонстрирует базовые возможности ООП: абстрактный класс, наследование, виртуальные функции и полиморфизм;
- использует `vector` и умные указатели `unique_ptr` из стандартной библиотеки.

Данные пока создаются непосредственно в `main.cpp`. Это временное решение. Оно позволяет проверить модель классов до подключения файлов и более сложной логики.

## Структура проекта и назначение файлов

```text
fintech-portfolio-service/
├── .gitignore
├── CMakeLists.txt
├── FinancialInstrument.h
├── FinancialInstrument.cpp
├── main.cpp
├── README.md
└── LICENSE
```

### `CMakeLists.txt`

Файл с инструкциями для системы сборки CMake.

Он сообщает CMake:

- как называется проект;
- что проект использует стандарт C++20;
- из каких `.cpp`-файлов нужно собрать программу;
- где находятся заголовочные `.hpp`-файлы;
- как назвать готовый исполняемый файл.

Благодаря CMake проект можно одинаково собирать из терминала и среды разработки.

### `FinancialInstrument.h`

Заголовочный файл с объявлениями классов финансовых инструментов.

В нём описан абстрактный класс `FinancialInstrument`. Это общий родитель для всех финансовых инструментов. Он содержит свойства, которые есть у любого актива:

- `symbol_` — короткое обозначение инструмента, например `AAPL`;
- `name_` — полное название;
- `price_` — текущая цена.

Метод `getType()` является чистой виртуальной функцией. Поэтому нельзя создать обычный объект `FinancialInstrument`: сначала необходимо выбрать конкретный тип инструмента.

От базового класса наследуются:

- `Stock` — акция;
- `Bond` — облигация;
- `Cryptocurrency` — криптовалюта.

Каждый наследник переопределяет `getType()` и возвращает собственное название типа. В дальнейшем в эти классы будут добавлены индивидуальные свойства. Например, для акции — биржа, для облигации — купон и срок погашения, для криптовалюты — название сети.

### `FinancialInstrument.cpp`

Файл с реализацией методов, объявленных в `FinancialInstrument.h`.

Разделение объявления и реализации нужно для того, чтобы:

- заголовочные файлы оставались компактными;
- код было проще читать и изменять;
- один класс можно было использовать в разных частях программы;
- проект было легче расширять новыми классами.

В этом файле конструктор сохраняет название, обозначение и цену инструмента. Метод `print()` выводит информацию, а методы классов-наследников возвращают конкретный тип актива.

### `main.cpp`

Точка входа в программу. Выполнение приложения начинается с функции `main()`.

Сейчас этот файл:

1. Выводит название программы.
2. Создаёт контейнер финансовых инструментов.
3. Добавляет в контейнер акцию, облигацию и криптовалюту.
4. Проходит по контейнеру и вызывает метод `print()` для каждого объекта.

В контейнере используется тип `unique_ptr<FinancialInstrument>`. Благодаря полиморфизму один контейнер может хранить объекты разных классов. Умный указатель автоматически освобождает выделенную память.

Во всех C++-файлах используется директива `using namespace std;`. Поэтому стандартные типы и функции записываются кратко: `string`, `vector`, `unique_ptr`, `make_unique` и `cout`, без префикса `std::`.

В дальнейшем `main.cpp` не должен содержать всю бизнес-логику. В нём останутся запуск программы и вызов консольного меню, а вычисления и работа с данными будут перенесены в отдельные классы.

### `.gitignore`

Содержит список файлов и каталогов, которые Git не должен добавлять в репозиторий.

Каталог `build/` создаётся автоматически во время сборки и не содержит исходного кода, поэтому хранить его в Git не нужно.

## Как собрать и запустить проект

Находясь в корне репозитория, выполнить:

```bash
cmake -S . -B build
cmake --build build
./build/fintech_portfolio
```

Назначение команд:

1. `cmake -S . -B build` — подготавливает сборку и создаёт каталог `build`.
2. `cmake --build build` — компилирует исходный код.
3. `./build/fintech_portfolio` — запускает готовую программу на macOS или Linux.

В Windows последняя команда может выглядеть так:

```powershell
.\build\Debug\fintech_portfolio.exe
```

Ожидаемый результат:

```text
Система управления финансовым портфелем

Доступные инструменты:
Акция: Apple (AAPL) — 230 USD
Облигация: US Treasury 10Y (US10Y) — 98.5 USD
Криптовалюта: Bitcoin (BTC) — 110000 USD
```

## Что нужно сделать дальше и для чего

Разработку следует продолжать небольшими последовательными этапами.

### Этап 1. Расширить классы инструментов

Что сделать:

- добавить в класс акции биржу и дивидендную доходность;
- добавить в класс облигации номинал, процент купона и дату погашения;
- добавить в класс криптовалюты название блокчейн-сети;
- проверить, что цена и другие числовые значения не могут быть отрицательными.

Для чего: показать различия между классами-наследниками и научиться хранить в них собственные данные.

### Этап 2. Создать классы `Position` и `Portfolio`

Что сделать:

- `Position` должна связывать финансовый инструмент с его количеством;
- `Portfolio` должен содержать название, денежный остаток и список позиций;
- добавить вычисление стоимости позиции и общей стоимости портфеля.

Для чего: перейти от простого списка доступных активов к настоящему пользовательскому портфелю.

### Этап 3. Добавить операции покупки и продажи

Что сделать:

- создать класс или структуру `Transaction`;
- реализовать покупку инструмента;
- реализовать продажу инструмента;
- проверять количество инструмента и виртуальный денежный остаток.

Для чего: автоматизировать основную задачу системы управления портфелем.

Все операции остаются учебными. Программа не должна отправлять заявки настоящему брокеру.

### Этап 4. Сделать консольное меню

Что сделать:

- просмотр инструментов;
- создание и просмотр портфеля;
- покупка и продажа;
- поиск, сортировка и фильтрация;
- формирование отчёта;
- выход из программы.

Для чего: пользователь должен управлять программой через понятный интерфейс, а не изменять исходный код.

### Этап 5. Добавить чтение CSV

Что сделать:

- создать каталог `data` и файл `instruments.csv`;
- создать отдельный класс `CsvReader`;
- читать строки файла;
- в зависимости от значения `type` создавать `Stock`, `Bond` или `Cryptocurrency`;
- обрабатывать отсутствие файла и неправильный формат данных.

Пример будущей структуры CSV:

```csv
type,symbol,name,price
stock,AAPL,Apple,230.0
bond,US10Y,US Treasury 10Y,98.5
crypto,BTC,Bitcoin,110000.0
```

Для чего: отделить исходные данные от программного кода. После этого новый инструмент можно будет добавить в файл без изменения `main.cpp`.

### Этап 6. Подготовить поддержку Parquet

Что сделать:

- определить общий интерфейс чтения данных;
- оставить `CsvReader` одной реализацией этого интерфейса;
- создать `ParquetReader` как вторую реализацию;
- подключить Apache Arrow только после того, как CSV-вариант будет полностью работать.

Для чего: CSV удобен для начала и ручной проверки, а Parquet понадобится позднее для большого объёма исторических данных и ML-проекта.

### Этап 7. Добавить пользователей и роли

Что сделать:

- создать класс `User`;
- добавить роли администратора, менеджера и наблюдателя;
- реализовать вход по имени пользователя и паролю;
- хранить не сам пароль, а его хеш;
- ограничить команды в зависимости от роли.

Для чего: выполнить требование методички о разделении ролей и авторизации пользователей.

### Этап 8. Добавить сохранение и отчёты

Что сделать:

- сохранять портфель и историю операций;
- восстанавливать данные после повторного запуска;
- формировать TXT- или CSV-отчёт;
- добавить обработку ошибок через собственные классы исключений.

Для чего: программа должна сохранять итоговую информацию и демонстрировать работу с потоками ввода-вывода и исключениями C++.

### Этап 9. Добавить оставшиеся требования методички

После появления работающей программы нужно отдельно проверить и продемонстрировать:

- минимум три уровня наследования;
- хотя бы один абстрактный класс;
- инкапсуляцию, наследование и полиморфизм;
- передачу параметров по ссылке и по значению;
- встроенные, пользовательские, дружественные и виртуальные функции;
- перегрузку методов и операторов;
- шаблон класса и шаблон функции;
- статические поля и методы;
- собственные классы исключений;
- пространства имён;
- динамическое выделение памяти и умные указатели;
- несколько паттернов проектирования;
- контроль ошибок файлового ввода и вывода.

Для чего: эти элементы прямо перечислены в задании курсового проекта и должны присутствовать не формально, а в понятных местах программы.

## Почему CSV и Parquet ещё не добавлены

CSV и Parquet относятся к слою хранения данных. Перед его созданием нужно определить, какие объекты программа хранит и какие поля есть у каждого объекта.

Правильный порядок разработки:

```text
Финансовые инструменты
        ↓
Позиции и портфель
        ↓
Покупка и продажа
        ↓
Консольное меню
        ↓
CSV
        ↓
Parquet
        ↓
Пользователи, отчёты и остальные требования
```

Так каждый новый этап можно отдельно собрать, запустить и проверить. Если сразу добавить базу данных, авторизацию, GUI и все паттерны, будет трудно понять, в какой части возникла ошибка.
